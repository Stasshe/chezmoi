# セッション→技術記事

会話全体を振り返り、作業内容を1本の記事mdにして `~/dev/articles/YYYYMMDD-<slug>.md` に書く。slugは英小文字ハイフン区切り。

## 手順

1. 会話を振り返り素材抽出: 目的 / ハマった点と原因 / 解決策 / 実コード・実コマンド / 教訓
2. プラットフォーム判定(下記)。判定理由を1行でユーザーに報告
3. 該当frontmatterでmd生成。デフォルト非公開(Zenn: `published: false` / Qiita: `private: true`)
4. 出力パスを報告して終了。公開作業はしない

## Zenn / Qiita 判定

- **Zenn**: 個人開発の過程・設計判断・アーキテクチャ考察・ツール/OSS紹介・深掘り解説。読み物として価値がある系
- **Qiita**: エラー解決・環境構築手順・設定Tips・ニッチなハマりどころ。検索流入で助かる系
- 迷ったら: 「エラーメッセージで検索して辿り着く記事」ならQiita、それ以外Zenn

## frontmatter

Zenn:
```yaml
---
title: ""
emoji: "🔧"
type: "tech"
topics: ["小文字英数のみ", "最大5"]
published: false
---
```

Qiita:
```yaml
---
title: ""
tags: ["タグ", "最大5"]
private: true
---
```

## 記事スタイル

- 常体(だ・である)。前置き・自己紹介・「いかがでしたか」系の締め 禁止
- 情報密度最大。文字数あたりの情報量を濃く。雑でよい、短くしろ
- 構成: 結論/成果 → 背景(最小限) → 本題(手順・原因・解決) → ハマりどころ
- コード・コマンド・エラーメッセージはセッションの実物を使う。創作禁止
- 秘匿情報(トークン・実パスのユーザー名・内部URL)はマスク
- 自明な説明・網羅的な代替案列挙 禁止。実際にやったことだけ書く
